## [0.3.0] - 2026-09-15

The studio ported over: the slide editor and its AI
assistant, generation options, studio-wide narration defaults with Kokoro, and a re-voice that keeps
step with the picture.

- [fix] **Re-voiced video stays in step with the picture.** Re-voicing an imported video rebuilds it as a single section, and only the *first* sentence of a section was pinned to the moment it was spoken — every sentence after it ran on immediately, so each pause in the original was squeezed out of the new narration while the picture kept it. The narration drifted further ahead with every pause, and on a clip with any real gaps the end was badly out of sync. Each sentence is now pinned to its own timestamp: the pause that followed it becomes its slack, whatever it does not use comes back as silence, and a sentence is only sped up when it would overrun the moment the next one is due (the last one stays inside its own slot so the video's end cannot cut it off mid-word). The speed asked of the voice is worked out per sentence too, against its own window, rather than once for the whole clip. The closing sentence may use the video's tail after the speaker stops (the narration is padded to the video and trimmed there), falling back to its own slot when the duration cannot be probed, and a small overrun is left alone rather than squeezed — Whisper often ends one sentence exactly where the next begins, and adjusting every one of those would make the speaking rate wobble. A re-voice in which every sentence fails to synthesise now reports failure instead of producing a silent video. Verified on a real clip: every sentence lands within ~10 ms of its original timestamp, against drift of up to five seconds before. `tests/test_revoice_sync.py` (11) — #revoice-sync
- [chore] **Log lines say `mediastudio`, not `pptx2video`.** The engine's logger root (and the eleven modules that named theirs directly) carried the predecessor's package name; every line in the desktop splash and the server log now reads `[mediastudio.VIDEO]`, `[mediastudio.IMPORT]` and so on. The optional environment overrides moved with it: `PPTX2VIDEO_PORT`, `…_OLLAMA_URL`, `…_OLLAMA_MODEL`, `…_OLLAMA_ENABLED`, `…_EDGE_TTS_VOICE`, `…_MUSIC_VOLUME`, `…_TRANSITION_PAUSE` are now `MEDIA_STUDIO_*`, matching `MEDIA_STUDIO_NO_BROWSER` — #log-name
- [docs] **GPU transcription.** Whisper runs on the GPU when the optional CUDA 12 runtime wheels are present (`pip install nvidia-cublas-cu12 nvidia-cudnn-cu12`, about 1 GB); without them the engine logs "GPU transcription failed … retrying on CPU" and continues on the CPU. Installed on the development machine and in its packaged app today; an in-app "Enable GPU transcription" action is on the list — #gpu
- [feat] **AI assistant on the slide editor** (porting vertical 3b). With a local Ollama the Slides card gains the AI actions Slide Studio had, run through the app's jobs with progress, per-slide error counting, **Cancel**, and results saved slide by slide: **Generate notes** for slides without any, **Enhance all** for natural narration, **QA review** (grammar, tone, flow, transitions per slide with an overall score, persisted on the project and shown as badges in the rail, each issue with a **Fix** button that asks the model to fix only that), **Tone** (technical, executive, student, sales, casual, formal or a custom brief), **Translate** (notes replaced in place, with an offer to switch the narration to a matching voice), **Pacing** (natural pauses, by rules or with the model), **Analyze** (a content check with a score and suggestions) and a **Q&A document** downloadable beside the video. Per slide, **AI Enhance** puts the model's rewrite into the editor as a proposal with **Revert**, never saving on its own. A status line shows the model in use and whether vision is on; slide images are only sent to a vision-capable model when they came from PowerPoint or a PDF, never the title-only fallback. `GET /ai/status`, `POST /ai/{notes,enhance,qa,tone,translate,pacing,qa-doc,analyze}`, `POST /slides/{i}/ai/{enhance,qa-fix}`, `GET /export/qa`, `POST /api/jobs/{id}/cancel` (`services/ai_slides.py`, `api/routers/ai.py`; the voice listing moved into `services/voices.py`). Verified live against gemma3:12b: an enhancement in 16 s, a QA review of the narrated slides scoring 7/10 with two issues. Tests: `tests/test_ai_slides.py` (32, the model mocked), `tests/test_jobs.py` (+2); vitest `lib/ai.test.ts` — #ai-assistant
- [feat] **Slide editor** (porting vertical 3a). A deck or PDF project now opens with a **Slides** card above Generate: a thumbnail rail (with dots for slides that have notes, a pencil for edited ones and an "Animated" badge), the selected slide's image with its title and text, and an editor for the speaker notes with **Save**, **Undo** (the engine keeps 20 steps), **Reset** to the deck's own notes, Ctrl+S and ← / → navigation; drafts survive switching slides, and **Save all** writes every edited slide at once. Each slide can carry a **voice override** (the voices of the project's narration provider) and a **pause after slide**; **Export .pptx with notes** downloads the deck with the edited notes written back in (`PPTXReader.export_with_updated_notes`, which existed but was never wired). **Render slide previews** exports the thumbnails through PowerPoint as a job — and that export now runs behind a lock shared with every generate path, closing a live race where two concurrent renders fought over the single PowerPoint instance; the source of the images (PowerPoint, the title-only Pillow fallback, or PDF pages) is recorded so the AI features can avoid the fallback. The per-slide state is the engine's own inner `project.json`, now created when the editor first opens rather than at the first render, with `ProjectManager.save()` serialising every field and `load()` tolerating newer files; a PDF's notes are no longer wiped on every generate. API: `GET/PATCH /api/projects/{id}/slides[/{index}]`, `POST …/slides/{index}/undo|reset`, `POST …/slides/render`, `GET …/slides/{index}/image`, `GET …/export/pptx` (`services/slides.py`, `api/routers/slides.py`). Tests: `tests/test_slides.py` (27, real deck and PDF fixtures, the lock proven with two threads); vitest `lib/slides.test.ts` — #slide-editor
- [feat] **Generation options** (porting vertical 2a). The Generate card gained a collapsible **More options** section, prefilled from Settings › Studio: slide **transitions** (the nine from Slide Studio — fade to black/white, crossfade, slide left/right/up/down, zoom in — with duration and pause), an **intro card** (title, subtitle, duration) and **outro card** (closing text, duration), a text **watermark** (position, opacity), a **subtitles** mode (none, per slide, or Whisper word-level SRT + VTT as a second pass), **extra formats** (WebM, GIF of the first 30 s, audio-only MP3) and a **Preview 15 s** button that renders only the opening, playable in its own player. Every produced file is recorded on the project and downloadable beside the video (`GET /api/projects/{id}/outputs/{kind}`); the new defaults (transition, duration, watermark text/position/opacity) live in Settings › Studio. Every option is pinned per job when the request arrives — nothing on the render path reads the shared config any more, so two concurrent jobs cannot interfere. Four engine defects had to be fixed for the options to actually work: transitions rendered at 2 fps (one frame per transition) and now render at 24 fps only when a transition is on; the horizontal slide effect was applied twice; an intro card shifted the narration, the subtitles and the chapter markers by its own duration (all three are now offset together, verified live: silence for exactly the intro's 3 s, speech from 3.0 s); and the title cards and watermark named a font by family (`Arial`), which Pillow cannot resolve on many hosts — they rendered as a black card and no watermark — so the engine now resolves a real font file with platform fallbacks and never drops the text silently. Whisper subtitles get their own file names and never overwrite the per-slide SRT; extra exports run with per-job flags; `burn_subtitles`/audio extraction use the bundled ffmpeg. Tests: `tests/test_generation_options.py` (new), extended `test_generate.py` and `test_studio_settings.py`; vitest `lib/generateOptions.test.ts` — #generation-options
- [feat] **Studio settings and Kokoro narration** (porting vertical 1 of 5 from Slide Studio). Settings › Studio exposes the engine configuration that only lived in `data/config.json`: the narration provider (**Edge TTS** or **Kokoro**, the local, offline voice that downloads its model once), the default voice for each, Kokoro's language, the Whisper model for transcription (with GPU/CPU notes), the Ollama model, the output folder, the transition pause and the music volume. Admins edit and save (partial updates, validated with readable messages); everyone else sees the values read-only. `GET /api/voices?provider=edge_tts|kokoro` lists either provider's voices — Kokoro degrades to its built-in list plus a notice when the model is not on disk, and to an empty list plus an error when a present model cannot load (nothing is cached in that case); Edge voices are served from a week-long cache with a stale-cache notice when Microsoft cannot be reached. Generate and Re-voice gained a **Narration** switch: the voice list follows the provider, the configured default is preselected, a request may omit the voice (the server fills in the default), a voice from the other provider is refused, and the provider is pinned per job (`VideoProcessor(provider=…)`, no global mutation, so concurrent jobs cannot interfere — including the audio onset profile used at assembly, which followed the studio default before). The Whisper model setting is the transcription default, resolved when the request arrives (an unknown model name is refused with a 400). `services/studio_settings.py`, `api/routers/settings.py`, `api/routers/media.py`, `frontend/src/components/settings/StudioCard.tsx`, `lib/studioSettings.ts`; tests `tests/test_studio_settings.py`, `tests/test_media_voices.py` (+ generate / re-voice / transcription cases). The porting specs for the next verticals live in `docs/porting/` — #studio-settings
- [fix] **Version shown once, from the API.** The sidebar footer printed a hard-coded version — still `0.1.0` inside the 0.2.0 build — and Settings wore a duplicate chip in its header. The chip is gone; the sidebar now shows the version the API reports, so an in-place update changes it, and `tests/test_version.py` refuses any hard-coded version string in the frontend source — #version-from-api

## [0.2.0] - 2026-09-14

The first release with the whole studio in place: projects, transcription, generate with
Vimeo presets, re-voice with translation, accounts with a configurable password policy,
self-update from Git, and the Windows desktop installer.

### Added

- [scaffold] Initial React + FastAPI skeleton for **Media Studio Enterprise**, the successor to Slide Studio Enterprise (NiceGUI). FastAPI backend (app factory, `/api/system/health`, session-cookie auth skeleton) reusing the carried-over Python media engine (`core/`, `utils/`, `services/processing.py`); React + Vite + TypeScript frontend on the OpenSight design system (theme tokens, shell, primitives, fetch client) with a login page and a dashboard landing state. Torch/Argos-free — translation runs on Ollama, transcription on faster-whisper/CTranslate2 — #rebuild
- [feat] **Projects screen** — the first real vertical. Import a slide deck, PDF, or video and see it in a table (type, slide count, size, import time) with delete. Backend `services/projects.py` store (one directory per project under `data/projects/`, deck slide-count via the carried-over `pptx_reader`) + an auth-guarded `/api/projects` router (list / import / get / delete, 2 GB cap, file-type validation). Frontend `pages/Projects.tsx` (React Query list + upload mutation), a Projects nav item, and the Dashboard's Projects / Import Video tiles now open it. `tests/test_projects.py` (7 tests) + `requirements-dev.txt` (pytest, ruff) — #projects
- [feat] **Video transcription with an editable transcript.** A project detail page (`/projects/:id`) transcribes an imported video with the carried-over faster-whisper engine (GPU with automatic CPU fallback) through a small in-process **job runner** (`services/jobs.py`) polled at `/api/jobs/{id}` — OpenSight's no-websocket model. The timed segments are stored on the project and shown as an editable transcript, saved via `PATCH /api/projects/{id}/transcript`. Adds `services/transcription.py`, the `/transcribe` + `/transcript` endpoints, and `tests/test_jobs.py` + `tests/test_transcription.py`. Verified end-to-end on a real 30 s clip (8 segments, en, CPU) — #transcription
- [fix] **Hardened project-id handling** (from the Projects-screen review). A crafted `pid` such as `%2e%2e` is now rejected before any filesystem join, so `get` / `delete` / transcript can never escape `data/projects/` (a delete would otherwise `rmtree` the data directory). Import also rejects unsupported types and oversize uploads from the request metadata before buffering the body; the Projects list now surfaces delete errors and announces its notice (`aria-live`) — #harden-projects
- [feat] **Generate video.** Turn a deck or PDF project into a narrated MP4. A Generate card on the project detail page picks a voice (Edge TTS, 300+), speed, and an **output preset** — including the **Vimeo-optimized** `vimeo_1080p` (~10 Mbps) and `vimeo_4k` (~30 Mbps), whose bitrate is wired through `VideoProcessor` → `VideoCreator` → the encoder. Generation runs the carried-over `VideoProcessor` pipeline (PowerPoint/LibreOffice slide render → TTS → moviepy) as a job (`POST /api/projects/{id}/generate`), polled like transcription; the result plays inline and downloads at `GET /api/projects/{id}/video` (path-traversal-guarded). Adds `services/output_presets.py`, `api/routers/media.py` (`/api/voices`, `/api/output-presets`), the generate/download endpoints, and `tests/test_output_presets.py` + `tests/test_generate.py`. Verified end-to-end on a real 40-slide deck → a 1080p 3m20s narrated MP4 — #generate
- [fix] Deck slide count showed as empty — `_slide_count` called the `PPTXReader.slide_count` **property** as a method, so the `TypeError` was swallowed to `None`. It now reads the property, and a valid deck reports its real slide count — #fix-slide-count
- [feat] **Re-voice.** Regenerate an imported video's narration in a new voice — and optionally a **translated language** (via the carried-over Ollama translator) — while keeping the original frames. From a transcribed video's detail page you pick a voice / speed / target language and re-voice: it reconstructs a section from the transcript, runs the carried-over `VideoProcessor._revoice_video` (per-sentence TTS timed to the original, then `replace_video_audio` with `-c:v copy` + a trailing-silence pad), and produces a `*_revoiced.mp4` that plays inline and downloads. Adds `POST /api/projects/{id}/revoice`, `GET /api/projects/{id}/revoiced-video`, `GET /api/languages`, `services/revoice.py`, and `tests/test_revoice.py` (8). The re-voice project state lives in a `pid/revoice/` subdirectory so it never clobbers the stored record. Verified end-to-end: a 30 s clip re-voiced (Brian) → a new MP4 with byte-identical 1080p frames and fresh narration — #revoice
- [fix] The generated- and re-voiced-video download links now carry a `download` filename, so they save the file rather than opening it inline (the inline `<video>` player is unaffected) — #download-attr
- [feat] **Self-update from Git.** Settings › Updates shows the installed commit/branch, checks upstream (`git fetch` + `HEAD..@{u}`), and — for admins — applies an update in place (`git pull --ff-only` + `pip install -r requirements.txt` into the running Python, as a job) then restarts the backend, which re-execs itself so the new code is served without a reinstall; the page waits for the backend to return and reloads. Degrades with a clear message when the install isn't a Git checkout or `git` is missing. `services/updater.py`, `api/routers/updates.py` (`GET/POST /api/system/update`, `POST /api/system/restart`), `tests/test_updater.py` (9, git/pip mocked). Verified live: restart re-execs to a fresh PID with the session intact — #self-update
- [fix] **Restart from an install path with spaces.** The packaged app's first in-app update pulled cleanly, but the restart never came back: on Windows `os.execv` is not an exec — the C runtime spawns a new process and joins argv with spaces **without quoting**, so under `…\Media Studio Enterprise\` (or any profile such as `C:\Users\Jane Doe`) the successor started as `python.exe C:\Users\jpore\AppData\Local\Media` and died on "can't open file" while the old process exited 0. `services/updater.py` now relaunches through `subprocess` (proper quoting) with the backend's stdio handed to the successor, keeping the desktop shell's log attached across restarts; POSIX keeps a true `execv`. A regression test performs a real restart from a directory with spaces (on the vendored 3.12 interpreter too, when present) and checks the argv the successor receives. Settings › Updates also bounds its "Restarting…" wait at four minutes (the desktop shell's own cold-start deadline), then says what to do and offers **Keep waiting**, instead of spinning forever; a failed restart request is now shown too. **Note for installs already deployed:** the update that delivers this fix is still restarted by the *old* code, so that one restart fails the same way — close and relaunch the app once, and every restart after it works — #fix-restart-spaces
- [feat] **Windows desktop installer.** Media Studio Enterprise now ships as one per-user NSIS installer, `dist\Media Studio Enterprise_<version>_x64-setup.exe` (~145 MB), built from `desktop/` with `npm run dist`: a small Tauri (WebView2) shell plus the official Python 3.12.8 embeddable runtime with `requirements.txt` installed into it (`scripts/fetch-python.ps1`; stamped by version + requirements hash, so it is idempotent). The app is staged as a **git clone of the repo's HEAD** with `origin` re-pointed at the GitHub remote (`scripts/stage-app.ps1`), so the install can fast-forward itself from Settings › Updates; the overlays are `boot.py` and imageio-ffmpeg's binary as `app\bin\ffmpeg.exe` — the engine calls ffmpeg by name and a customer machine has none, so `boot.py` puts `app\bin` first on PATH and sets `IMAGEIO_FFMPEG_EXE` (ffprobe is not bundled). Staging refuses to ship `.env`, `config.json`, `.storage_secret`, `*.db` or a venv, and proves the staged tree imports on the vendored runtime. The shell (`src-tauri/src/main.rs`, `server.rs`) runs `python\python.exe app\boot.py --port 5680 --app-dir app` with no console window, drains its output into a startup log the splash streams live, ties it to a kill-on-close job object (closing or killing the window always takes the backend with it, restarted or not), probes `/api/system/health` from Rust, then points the window at `http://127.0.0.1:5680` — or a free port when 5680 is taken. A failed start shows the backend's last lines with Retry (restart in place), Save report (`startup-report.txt` in the data folder), Copy and Open data folder; `scripts/check-environment.ps1` ships under `provisioning\` and prints an OK/WARN/FAIL row per dependency with a fix for each. Installs into `%LOCALAPPDATA%\Media Studio Enterprise\` (`app\`, `python\`, `media-studio-desktop.exe`, `uninstall.exe`; silent install with `/S`). Data stays **inside** that tree — `app\data\` and `app\assets\finished\`, because `utils/config.py` and `api/store.py` resolve their paths from the app root — which is why the install is per-user, and why the uninstaller leaves those folders behind (INSTALL.md records the limitations) — #desktop-installer
- [fix] **Desktop packaging review batch.** From the Reviewer gate on the installer commits: `services/updater.py` runs git with `GIT_TERMINAL_PROMPT=0` and `GCM_INTERACTIVE=never`, so a private remote with no stored credential fails fast with "Could not reach the Git remote" instead of hanging on a prompt nobody can see, and the fetch that runs on every Settings visit is bounded at 45 s. `check-environment.ps1` reports a missing dependency as a FAIL/WARN row instead of aborting (PowerShell 5.1 turned a probe's first stderr line into a terminating error), looks for the vendored `app\bin\ffmpeg.exe` before PATH, and gains a `git (self-update)` row. `stage-app.ps1` refuses a dirty tree, a HEAD ahead of its upstream or a branch with no upstream (`-Force` overrides, with warnings) — the installed checkout can only fast-forward from a commit the remote has — and checks that before removing the previous stage. `collect-installer.ps1`'s wrong-version error is formatted correctly (`-f` bound tighter than `+`); `fetch-python.ps1`'s pywin32 probe can no longer abort the vendoring step just before its stamp is written. In the shell, `opener:allow-open-path` is scoped to the install and app-data paths so "Open data folder" works, and the splash says when it could not open the folder; `server_ready` and `restart_server` run off the UI thread (`#[tauri::command(async)]`) so the splash no longer freezes during a health probe or a restart; a release build no longer falls back to the developer's checkout path baked in at compile time when its resources are missing — it reports the packaged location it looked in. `boot.py` prepends `app\bin` to PATH once, not once per in-app restart. `.gitignore` gains `/assets/` (render output) and `.env`, so neither ships nor dirties the installed checkout. New tests: `tests/test_boot.py` (verbatim-prefix stripping, the PATH guard, the "install is incomplete" exit), `tests/test_no_state_tracked.py` (no state or secret file is tracked; runtime files are ignored) and `tests/test_version.py` (all nine version carriers agree). `desktop/package-lock.json` is committed for reproducible shell builds — #desktop-review
- [chore] **Built UI tracked in git.** `frontend/dist` is committed from now on, so the installed app's `git pull` updates the UI as well as the backend; `stage-app.ps1` no longer overlays it — the clone carries it, and staging fails when the committed tree has no `frontend/dist/index.html`. `npm run build` in `frontend/` now also writes `frontend/dist/build-info.json`, a deterministic fingerprint of the source that produced the build (`frontend/scripts/build-info.mjs`: `src/`, `public/`, `index.html`, `package.json`, `package-lock.json` and the Vite/TS configs, tests excluded), and `tests/test_frontend_dist.py` recomputes it, so a source change committed without rebuilding and committing `frontend/dist` fails the test suite (it also checks that `index.html` references only assets that exist and that `frontend/dist` is tracked). After changing the frontend: `npm run build`, then commit `frontend/dist` with the change — #ui-in-git
- [feat] **Accounts and a configurable password policy.** The Enterprise edition now has real account management, ported from OpenSight's shape. Admins create accounts under **Settings › Accounts** (name, username, initial password, role `admin` / `editor`), edit them, reset passwords and deactivate / reactivate them — nothing is ever deleted, and deactivation ends the account's sessions at once. Everyone changes their own password under **Settings › Your account**. New and reset accounts — and the seeded `admin` on a fresh install — must set a password of their own at first login: the app shows a gate page instead of the studio, and the API refuses everything but the auth routes until the change is made (`403 password_change_required`), so `admin` / `admin` cannot survive first use from the UI or from a script. The password rules are a **policy admins edit under Settings › Password policy** — minimum length, upper-case / digit / symbol requirements, no username inside the password, a built-in common-password denylist — stored in the app config and enforced by one `validate_password` on every path that sets a password (create, reset, change); the live rules are shown beside every password field. Blank, space-padded and over-72-byte (bcrypt's limit) passwords are always rejected. Backend: `api/store.py` (roles, `is_active` / `must_change_password` / `last_login` with an in-place migration for existing databases), `api/routers/users.py`, `api/routers/settings.py`, `api/passwords.py`, `POST /api/auth/change-password`, the gate in `api/deps.py`. Frontend: `pages/ChangePassword.tsx`, `components/settings/{AccountsCard,PasswordCard,PasswordPolicyCard}.tsx`. Tests: `tests/test_users.py`, `tests/test_passwords.py`, `tests/test_settings_policy.py` — #accounts
- [chore] **Frontend dev server moved to port 5681** (from 5273): it pairs with the 5680 backend, and 5273 collided with the Pentaho Content Editor's Vite on the same machine, which made that editor silently fail to open while Media Studio's dev server was up. `frontend/package.json`, `vite.config.ts`, the CORS allow-list in `api/app.py`, the launch entries and the docs all moved together — #dev-port
- [docs] **Installer and desktop documentation.** New `INSTALL.md` for the people who install and run the desktop edition: requirements, install and silent install, first launch, where data and videos live, updating from Settings › Updates and what it needs, what the uninstaller leaves behind and how to remove it by hand, troubleshooting. `README.md` gets a current status (what is shipped), a Desktop edition section and the commit-`frontend/dist` rule. `VERSION.md` lists all nine version carriers and notes that the desktop exe's file version is compile-time — a `git pull` updates the version the API and UI report, not the exe or Add/Remove Programs, so a bump implies a new installer. `desktop/README.md` corrected: ffmpeg **is** vendored, staging is a git clone plus overlays (not a file copy), data lives **inside** the install tree, and self-update exists; it now covers the staging gate, the git + credentials requirement, uninstall/reinstall semantics and the known limitations — #docs-desktop
